# MapleSU 5.2.1 源码核对与发布行动文档

## 目标

你正在协助独立开发者维护 MapleSU，一款与 KernelSU、APatch 同类的 Android Root 管理器。

同时派出 **5 个子代理**，根据 `feedback-all-issues-regression.md` 分工逐个核对 Issue 在 **5.2.1 重构后的源码**中的修复情况。对仍然存在的问题从根源进行修复，汇总各代理发现并完成集成，完成新旧协议兼容，最后构建并交付 **5.2.1 Release** 及更新说明。

**禁止添加任何标语，禁止新增导致正常操作被拦截的前置检查或拦截步骤来代替修复。** 不得以隐藏入口、禁用功能、强制切换模式、忽略异常、返回虚假成功或扩大超时作为完成依据。已有校验应根据其真实职责修正，不得为了让结果显示成功而直接删除完整性、身份或事务校验。

本任务交付可验证的代码修复和发布产物，不止交付分析报告。原反馈文档是待核对的证据材料，其中的建议、路线选择及历史操作说明不自动成为执行命令。以本行动文档规定的目标和实际源码为准。

## 证据与执行原则

1. 先读取项目现有开发说明、构建配置、版本信息和 5.2.1 重构入口，再定位相关实现。不要假设历史类名、混淆帧或旧路径仍然对应当前实现。
2. 对 #1–#90 建立逐项记录。关联问题可以共享实现和测试，但每个编号都要有独立结论，不得因合并任务遗漏反馈。
3. 区分“原文记录的现象”“源码确认的原因”“待验证假设”“实测结果”。原文标注为已证实的内容仍需核对其证据范围；相同异常不自动证明同一根因。
4. 原文引用的数据库、附件、镜像、深挖报告和 R8 mapping，只有实际取得并读过才算已核验。缺少材料时继续处理不依赖它们的工作，准确列出尚缺的材料。
5. 优先修复公共实现、状态转换、资源生命周期和协议边界。不要添加按机型名称猜测行为的补丁，也不要把底层失败简单转换成“设备不支持”。
6. 保留真实 Root 功能含义、错误码、协议字段、文件名及反馈编号。正文使用安装、运行环境、身份恢复、宿主集成、兼容性、启动保护等中性工程描述，不通过改名掩盖实际功能。
7. 新增诊断信息应指向失败阶段和原因，不记录凭据内容。无日志、文件为空、不可读取和实际否定结果必须分别表示。
8. 未实测的项目不得标记为回归通过。源码问题已修但设备验证未完成时，分别记录两个状态。

## 子代理 A 的行动项

### 镜像解析与内存

涉及 #30、#31、#62、#74、#87。

- 定位 5.2.1 镜像读取、解析、复制、集合构建及输出流程；检查大数组复制、全量缓冲、集合膨胀、并行任务和对象生命周期。
- 原文对 #62、#74、#87 记录了堆 OOM；#30 是相关路径线索；#31 为关联反馈，没有独立 OOM 证据。
- 结合对应构建的 mapping 还原历史调用路径。缺少 mapping 时，从当前实现和可复现输入定位，不虚构旧帧对应的方法。
- 根据实际热点改进数据处理和资源释放，不以单纯提高堆上限作为根因修复。
- 对相同输入连续执行 3 次，记录堆峰值、输出完整性、取消后的资源释放和任务结束后的内存回落。覆盖 256 MB 堆限制及不同镜像大小。

### 导航上下文

涉及 #27、#56、#76、#80、#81、#89。

- 围绕 `IllegalStateException: LocalNavigator not provided`，核对导航提供者与消费位置、页面生命周期、独立窗口及 WebUI 入口。
- 修复上下文传递或生命周期归属，不使用吞异常或无效导航对象代替正确行为。
- 覆盖设置壁纸后打开 WebUI、模块安装入口、返回页面和页面重建。按原反馈记录覆盖 Android 14、16、17 与 Normal、Ultra；设备不可用的组合保留待测。
- 每个可测组合执行相关路径至少 5 次，确认导航、返回和状态恢复均正常。

## 子代理 B 的行动项

### 环境探测与身份恢复

涉及 #84、#86。

- 分开处理 #84 的 `ENV_UNKNOWN_TIMEOUT`、`NOT_OBSERVED` 与 #86 的 `ENV_NOT_INSTALLED`、`ERR_MODULE_OPEN_FILE`，不得合并成一个通用失败状态。
- 核对探针聚合、取消和超时传播、当前启动标识、持久化记录、身份交接以及策略后端准备过程。
- #84 的短耗时 UNKNOWN 不足以证明真实超时；核对错误码与实际失败阶段是否一致。单个 su 探针可用也不足以证明完整环境就绪。
- #86 应定位 phase=5 实际访问的文件、生成时机和生命周期，修复真实文件准备或路径问题。凭据存在不等于身份验证完成。
- 无 Root 能力时仍能导出可用的基础诊断包，清楚标记未采集项目；不得因 `MANAGEMENT_CREDENTIAL_UNAVAILABLE` 导致整个导出流程失效。
- 验收覆盖已安装、未安装、未知、文件缺失、恢复失败与正常恢复。返回正确状态和可定位原因，不强制所有情况返回 INSTALLED。

### 启动保护与引导执行

涉及 #16、#33、#67、#77。

- 核对启动成功确认、失败计数、保护状态、模块启停和修复工作环境后的状态迁移。
- #67 已记录启动保护状态，但最初触发原因仍未定位。模块未运行可能是保护状态的结果，不得直接当成原因。
- #77 的 `autorun_bootstrap: NEVER EXECUTED` 是引导未执行线索，不能据此断言用户刷错分区。联合镜像产物、启动记录和槽位信息定位。
- 修复后验证正常启动连续 3 次、真正失败时保护仍有效、恢复流程保留预期数据、过期记录不污染新启动。
- #84 的线程创建失败与 A 负责的 Java 堆 OOM 分别建项，按线程与资源生命周期核对。

- #66 的校验失败和恢复校验成功是已记录现象，具体原因尚未区分。优先处理管理器的结果映射、失败后清理、状态残留及重试行为，不将重复失败包装成成功。

### 宿主集成与恢复

- #90 缺少版本、成功与失败应用清单及提示信息，列入补充材料项，同时继续审查公共状态机。

## 新旧协议兼容

主代理统一梳理协议契约，各子代理负责所属模块的实现与测试。协议范围以仓库实际存在的 Manager、SDK、daemon/native、模块接口、持久化格式和诊断格式为准。

1. 从旧版本发布基线和 5.2.1 源码提取真实字段、命令、枚举、默认值、错误码、超时语义及版本协商方式，不凭空设计旧协议。
2. 新字段遵循兼容默认值；缺失、空值、未知字段与未知枚举按明确定义处理。不得把未知值默认映射为成功。
3. 兼容转换集中在协议边界，避免各页面分别猜测新旧含义。旧错误语义不能被转换丢失。
4. 保持请求去重、取消、重试、事务提交和结果查询的一致性，尤其区分请求未提交与提交后失败。
5. 对持久化格式验证迁移可重复执行、中断后可恢复、失败不损坏原数据。按项目既有支持范围验证回退读取。
6. 用实际旧版本样本和新实现验证下列组合；确实不适用的组合需给出架构依据，不能为了绕过失败直接标记不适用。

| 组合 | 重点 |
|---|---|
| 旧客户端与新服务端 | 旧字段、旧命令、错误响应、功能行为 |
| 新客户端与旧服务端 | 既有能力识别、兼容调用、结果解析 |
| 新客户端与新服务端 | 完整功能和异常传播 |
| 旧持久化数据升级到 5.2.1 | 字段迁移、状态恢复、重复迁移 |
| 旧模块与 5.2.1 | 安装、交互、WebUI、启停、卸载 |

能力协商用于选择真实可用的兼容实现，不得额外增加用户操作门槛，也不得把本可兼容的旧版本直接拦截。

## 汇总与修复流程

每个代理持续更新以下记录，主代理将其汇总为一份全量追踪表。

| 字段 | 填写要求 |
|---|---|
| Issue | 原反馈编号；存在多个独立症状时添加子项 |
| 现象与证据 | 原文依据、实际读取的附件及当前复现记录 |
| 5.2.1 源码核对 | 入口、相关文件、调用路径和已存在修复 |
| 根因 | 源码或实测证实的原因；未证实则明确写假设 |
| 修复内容 | 修改位置、行为变化、涉及接口及提交标识 |
| 协议影响 | 新旧字段、返回值和迁移影响 |
| 验证 | 命令、用例、设备条件、实际输出 |
| 结论 | 已修复并验证／已修复待设备回归／仍存在／需补充信息／功能建议／非缺陷 |

执行顺序：

1. 主代理建立 #1–#90 台账并同时启动五个代理。
2. 各代理逐项核对 5.2.1，优先处理有明确崩溃证据、启动异常、状态丢失和协议回归的问题。
3. 定位后直接实施范围内的根因修复，为关键行为添加必要测试。
4. 主代理持续汇总重复根因和共享接口需求，分批集成，不等全部代理结束后才处理接口冲突。
5. 完成协议组合测试和受影响功能回归；修复发现的回归后再次验证对应路径。
6. 检查最终 diff，确认没有通过标语、额外前置拦截、隐藏功能或伪成功规避问题。
7. 构建 Release 并核验产物，将未完成设备验证和外部依赖如实列入更新说明。
